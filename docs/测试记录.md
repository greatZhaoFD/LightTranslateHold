## 2. 按住热键 → API → 浮窗（mock）

- 配置：`trigger=Alt+1`，`triggerMode=hold`（现在按下即触发）
- 启动：`LightTranslateHold.exe --tray --allow-injected --data-dir <test-dir> --debug-fake-selection Hello --debug-popup-screenshot <png>`
- 输入：模拟 Alt+1 keydown，保持约 50ms 后 keyup（验证轻按也能触发）
- 结果：
  - 键盘钩子识别 Alt+1，150ms 后开始翻译（日志 `translation begin`）
  - 释放修饰键后取词（测试用假选区，验证链路）
  - mock API 收到 `"Hello"`，SSE 流式返回
  - 浮窗显示“English → 中文”和模拟译文，`DrawToBitmap` 截图成功
- 截图：`docs/popup-en-zh.png`、`docs/popup-zh-en.png`（中文输入 → 英文）

说明：`--debug-fake-selection` 仅用于在无法访问真实前台窗口/剪贴板的自动化会话中验证“热键→取词后链路→API→浮窗”。它不是正常使用路径。

## 3. 浮窗行为

- 通过 `EnumWindows` 检查：
  - 显示时窗口 `visible=True`，ExStyle 包含 `0x08000000`（WS_EX_NOACTIVATE）、`0x00000080`（TOOLWINDOW）、`0x00000008`（TOPMOST）
  - 无操作等待 8 秒后窗口**仍然可见**（已移除自动消失）。
- 关闭方式：`Esc`（键盘钩子）或点击浮窗外（新增全局鼠标钩子）；点击浮窗内（例如“复制”）不会关闭。
- 多显示器定位：当前虚拟桌面有 3 个显示器，浮窗按光标所在屏幕的工作区钳制，未超出屏幕。
- 复制按钮/滚轮/外部点击为鼠标交互，当前锁定桌面无法做真实点击验证；代码路径已审查。

## 5. 内存观测

同一进程，使用 `Get-Process` 读 WorkingSet64 / PrivateMemorySize64：

| 时刻 | 工作集 | 私有内存 |
|---|---:|---:|
| 启动约 2s | 37.9 MB | 24.6 MB |
| 空闲 13s（空闲回收后） | 0.23 MB | 24.6 MB |
| 完成一次翻译后 | 0.35 MB | 33.3 MB |

说明：程序在空闲/浮窗隐藏后调用 `EmptyWorkingSet`，所以工作集会显得很小；私有内存更能反映真实占用，空闲约 25 MB，加载 UIA/浮窗后约 33 MB。不同机器、.NET 版本和 API 响应长度会有差异。

## 7. 启动行为

- 空数据目录首次启动（无配置文件）：双击 EXE 后自动显示设置窗口，已通过窗口枚举验证（标题“轻译 · 按住版设置”）。
- 已有配置文件、已保存 Key 的后续启动：不再弹设置窗口，静默进右下角托盘；窗口枚举无可见窗口。
- 开机自启（`--tray`）：始终静默进托盘，不弹窗。
- 未配置 Key 时托盘提示“未配置 API Key，右键设置”。
